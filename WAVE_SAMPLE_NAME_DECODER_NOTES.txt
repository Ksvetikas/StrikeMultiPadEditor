Wave sample-name decoder integration
=====================================

Added: WaveSampleNameDecoder.cs

The decoder uses this verified lookup chain:

  2-byte KITI reference
    -> 8-byte translation record
    -> 50xx sample index
    -> wave_list_sort_name.lst record number
    -> sample name

Translation record layout (8 bytes):
  +0x00..+0x01  secondary reference
  +0x02..+0x03  50xx sample index
  +0x04..+0x05  00 00
  +0x06..+0x07  KITI reference

The translation table is located by finding the long consecutive run of
8-byte records whose sample indexes start at 0x5000 and increment by one.
The name table uses 0x90-byte records; the big-endian record number at the
start of each record is the sample index's low byte, and the ASCII name
starts at +0x10.

Verified against Backup005.bkf:
  KITI reference 1F 83 -> index 0x3F (63) -> 17 TimpF#1 b
  KITI reference 1F 9C -> index 0x5C (92) -> 808Low

The existing LayerSampleNameResolver remains in place and retains priority
for the candidate layer references it already resolves. The new factory
lookup is used as a fallback and is also included in the
COPY SAMPLE REFERENCE RESULTS clipboard report.

The names and offsets are shown as source-derived lookup results. This does
not establish that the translation table's two-byte references correspond
to physical pads or to Candidate A/B layer assignments.
